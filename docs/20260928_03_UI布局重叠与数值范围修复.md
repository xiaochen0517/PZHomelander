# 20260928_03 UI 布局重叠与数值范围修复

## 问题现象

`SettingsWindow.lua` 设置窗口存在两类问题：

1. **展示样式问题**：窗口尺寸偏小，标题超出窗口；按钮文字超出按钮边框；同一行内按钮文字与标签描述文字（如模式按钮 `At Least`/`At Most` 与状态标签 `Health`/`Overall Health`）横向重叠。
2. **数值范围与展示问题**：怀疑 `Hunger`/`Thirst` 等状态的可调范围写成 `0.0~1.0` 但真实上限应为 `100`；数值展示小数位不固定，长了会超出布局；加减按钮每次调整的步长偏小，调节不便。

## 原因分析

### 布局重叠

原实现（见 `git log` 中 `ffe39af`）里各列（启用按钮、标签、模式按钮、加减按钮、数值）的 x 坐标全部是写死的像素常量（如 `ROW_X + 90`、`ROW_X + 170`），没有依据实际文字宽度计算。当标签文字长度超过预留间距（例如 `Overall Health` 比 `Health` 长很多）时，紧随其后的模式按钮列就会与标签文字重叠；窗口整体宽高（`370x260`）也是固定值，未考虑标题文字和内容的实际占用宽度，导致标题溢出窗口边界。

### 数值范围排查

对 `tmp/decompiled/zombie/characters/CharacterStat.java` 和 `Stats.java`（游戏本体反编译源码）核实：

```java
public static final CharacterStat HUNGER = register("Hunger", 0.0F, 1.0F, 0.0F);
public static final CharacterStat THIRST = register("Thirst", 0.0F, 1.0F, 0.0F);
public static final CharacterStat FATIGUE = register("Fatigue", 0.0F, 1.0F, 0.0F);
```

`Stats.set(stat, value)` 内部会调用 `stat.clamp(value)`，强制把写入值钳制在 `[minimumValue, maximumValue]` 区间内。

**结论：`Health`（0~1）、`Hunger`/`Thirst`/`Fatigue`（0~1）、`Overall Health`（0~100）在 `StatLocks.lua` 中的范围定义本身就是正确的，真实上限不是 100。** 如果改成 0~100，写入 80 这类值会被游戏底层直接钳制为 1.0，反而会制造新的状态异常——这正是需求描述中担心的"限制之后状态出现问题"，但病因在于误判范围，而非原有代码有误。故本次未修改任何 `min`/`max` 字段。

## 修复方案

### `client/Homelander/UI/SettingsWindow.lua`

- 新增 `computeLayout()`，通过引擎 API `getTextManager():MeasureStringX(font, text)` 实测各列文字的真实渲染宽度（启用按钮 ON/OFF、状态标签、模式按钮 At Least/At Most、数值列），据此动态计算每列的 x 坐标与宽度，替代原先写死的像素坐标，从根源上避免因文字长度变化导致的重叠/溢出。
- `createChildren()` 中按计算出的总宽度、标题文字宽度、行数动态得出窗口的目标宽高，与初始宽高不一致时调用 `setWidth/setHeight/setX/setY` 自适应放大并保持窗口居中，标题不再超出窗口。
- 数值展示统一改为 `string.format("%.2f", setting.value)`，固定两位小数，避免浮点运算产生的多位小数导致展示超长。
- 行高由 32 调整为 34，列间统一预留 `COL_GAP = 12` 的间距。

### `shared/Homelander/StatLocks.lua`

- `min`/`max` 范围保持不变（已通过反编译源码核实为正确值）。
- 加减步长统一调整为"最大值的十分之一"：
  - `health`：`0.05 → 0.1`
  - `overallBodyHealth`：`5 → 10`
  - `hunger`/`thirst`/`fatigue`：`0.05 → 0.1`

## 结论

- 布局重叠的根因是坐标写死、未随文字实际宽度自适应，已改为基于 `MeasureStringX` 的动态布局并联动窗口自适应尺寸。
- 数值范围排查后确认原定义正确（`Hunger`/`Thirst`/`Fatigue` 真实范围就是 `0.0~1.0`，并非 `100`），未做改动，避免因误改范围触发游戏底层 clamp 导致新的状态异常。
- 数值展示固定两位小数、步长改为最大值的十分之一，两点均按需求直接实现。
