# 20260928_01 属性锁定 Mod 实现

## 背景

仓库最初是从 `PZExampleMod` 模板复制而来的 PZ Build 42 Lua Mod 骨架，内容是通用示例（示例窗口、示例物品、client↔server 网络往返）。根据 `tmp/` 下两份分析文档（`PZ_健康死亡系统API说明.md`、`属性锁定与免死方案分析.md`，未纳入版本控制）的结论，实现一个「属性锁定」功能：为角色的多种状态设置目标值 + 方向，受伤或状态变化时自动纠正。

## 需求

1. 支持多种状态类型（血量、口渴等）分别配置目标值 + 方向（不低于/不高于），受伤时把对应值钳制住。
2. 模组名称与图标要跟项目文件夹名（`Homelander`）同步。
3. 每个状态项可单独开关，且设置要在重启游戏后保留。
4. 纯 Lua，逻辑尽量简单，不过度设计。

## 改动内容

### 0. 检查点 commit

在做任何改动之前，先提交一份 `PZExampleMod` 模板原始状态（`96e0be8`），作为可回滚的检查点。

### 1. 目录重命名（PZExampleMod → Homelander）

- `contents/mods/PZExampleMod/` → `contents/mods/Homelander/`，`media/lua/{shared,client}/PZExampleMod/` → `.../Homelander/`
- 删除整个 `media/lua/server/PZExampleMod/`、`media/scripts/`（示例物品）、`shared/Network.lua`、`client/Events.lua`、`client/Commands.lua`、旧 `UI/ExampleWindow.lua`——本功能纯本地/客户端，不需要 client-server 网络往返
- `mod.info` / `workshop.txt`：`name`/`id` 改为 `Homelander`，`description` 改为描述属性锁定功能
- `poster.png`：仓库原有的通用占位图，原样带到新目录结构，未生成新美术资源

### 2. 属性定义 + 纠正逻辑（`shared/Homelander/StatLocks.lua`）

- `StatLocks.Definitions`：5 项状态（血量 `health`、综合健康 `overallBodyHealth`、饥饿 `hunger`、口渴 `thirst`、疲劳 `fatigue`），每项含取值范围、默认方向/数值、单步调整量、`get`/`set` 访问器
- API 来源已核对反编译源码：`IsoGameCharacter.getHealth/setHealth`、`BodyDamage.getOverallBodyHealth/setOverallBodyHealth`、`BodyPart.getHealth/SetHealth`（注意大写 S）、`Stats.get(CharacterStat)/set(CharacterStat, float)`
- 锁定 `overallBodyHealth` 时必须同步钳制各 `BodyPart.health`，否则下一 tick 会被游戏自身的汇总计算覆盖
- `StatLocks.applyTo(player)`：每 tick 检查一次，只在数值越过阈值时才纠正，由 `client/Homelander/Bootstrap.lua` 的 `Events.OnPlayerUpdate` 调用

### 3. 持久化

使用 PZ 原生 `getFileWriter`/`getFileReader` 写入 `Zomboid/Lua/Homelander_Settings.ini`，与存档无关，重启游戏后自动读回。格式为简单的 `key.field=value` 行，读不到文件/字段时回退到默认值（`enabled` 默认 `false`）。

放弃了 `PZAPI.ModOptions` 方案——反编译的 jar 里找不到 `ModOptions` 类，无法验证其行为。

### 4. UI（`client/Homelander/UI/SettingsWindow.lua`）

复用现有 `ISPanel:derive`/`ISButton` 写法（未引入未验证过的 `ISTickBox`/`ISTextEntryBox`），每个状态一行：`[启用/禁用]  标签  [不低于/不高于]  [-]  数值  [+]`，点击立即保存并刷新按钮文字。侧栏按钮（`SidebarButton.lua`）复用原生 `Client_Icon` 纹理，点击切换设置窗口。

## 已知限制

- 纠正基于逐 tick 检查，存在一帧滞后；对武器命中/载具撞击这类同步完成扣血与死亡判定的瞬时伤害，理论上仍有极端漏判窗口，未实现"免死"专题的武器命中钩子兜底
- 逻辑只应用于本地控制的玩家

## 验证方式

无可运行的本地 PZ 环境，需要用户自行在游戏中验证：挂载 Mod → 打开设置窗口 → 启用一项锁定 → 用作弊菜单破坏对应属性 → 观察下一 tick 纠正 → 重启游戏确认设置保留。
